2026-07-18 · Pricing · Postern Desktop

Postern Desktop moves to 2 years free, then a key — mobile stays free forever, and here is what it means for your data: nothing.

We are narrowing a promise we published. Our stated pricing line was "personal editions stay free regardless" — and it still holds for mobile: the mobile OS and every personal app on mobile stay free forever, our free adoption channel, untouched. The only thing changing is Postern Desktop (the personal desktop suite), which now reserves the right to require a license in the future: each desktop install is free for 2 years (the adoption on-ramp), after which a personal key keeps updates and premium features coming. We are announcing this loudly and in plain language because narrowing a published promise quietly would be exactly the kind of dark pattern we refuse to run.

What changes for your data: nothing. The key gates updates and premium features — never access to your own encrypted data. Decrypt, read, and export of every vault, wallet, credential, message, and backup you already have always work — key or not, expired or not — and safety actions like Panic Lock always fire. After 2 years with no key a desktop app enters a read-only grace mode: it fails open, never into a lockout, and your data is never held hostage.

One more change, stated plainly: free versions may now show ads — but only the privacy-preserving kind. Free versions (all personal mobile apps, and Postern Desktop during its free window) may show contextual, non-tracking ads: chosen from nothing but the current screen, with no profile, no advertising or device ID, no third-party ad SDK, no telemetry, and no data leaving your device, always clearly labeled. Surveillance, behavioral, programmatic, and tracking-based ads are forbidden. Ads never appear in Panic Lock, Vault decrypt/export, or backup, and the paid Postern Desktop key removes ads entirely. Our promise of "no ads that track you" is unchanged — this narrows it to "contextual, no-tracking only," it does not walk it back.

Ads: contextual and non-tracking only
Free versions may show ads based only on the current screen — no tracking, no profile, no device ID, no telemetry, nothing leaves the device, always labeled, never in security-critical flows. The Desktop key removes ads. Surveillance/behavioral advertising is forbidden.

Existing installs grandfathered

There is no payment integration and no price today, the per-install free-window clock is not built, and no ad system is built — no ad network is integrated and no placements ship. 2026-07-16 · Bloch node v0.1.0-alpha3

Two consensus fixes the k-ramp exposed — the network converges again.

Relaxing the gate back to k=4 (alpha2) un-choked block production — and that surfaced two latent consensus bugs that had been masked while the chain crawled: non-mining nodes stopped converging (they froze on ingest) and the sole miner ran away. Both are fixed here; both are backward-safe — historical blocks validate byte-for-byte, so there is no fork.

Finality checkpoint — unit fix
The finality checkpoint was computed in blue-score but enforced in height; once the DAG-width skew passed the checkpoint depth, a node "finalized" a height above its own tip and permanently rejected every chain-extending block. It now uses the selected tip's height, and a one-time startup clamp heals the poisoned value. Ingesting nodes converge again.
ASERT difficulty — height-switched re-anchor
ASERT clamped the absolute schedule exponent to ±4×, a lifetime cap — difficulty could never exceed 4× the genesis target however much hashrate joined (ASICs/FPGA included). A height-switched re-anchor resets the schedule and — only for the re-anchored regime — widens the bound so difficulty tracks real hashrate. Blocks below the anchor keep the old bound byte-for-byte.
Verified live
Two nodes were reset to a shared base and converged on the re-anchored chain, both mining — the finality fix confirmed by nodes accepting the blocks they previously froze on. Unaudited; the coin has no value; Bloch is ownerless — a candidate release operators adopt, not a mandate.

2026-07-16 · Bloch node v0.1.0-alpha2

Difficulty-driven k-ramp — the fixed k=8 gate is retired.

The Module-SIS residual gate no longer jumps to a fixed k=8 — which had been misapplied onto the live chain and was choking block production at low hashrate for no security gain (the source flags both k=4 and k=8 as the trivial q-ary regime at β=q/16). It now rides the network's own ASERT difficulty — the Bitcoin model: more hashrate → higher difficulty → higher k.

k = 4 now, rising with hashrate
k stays 4 below a future activation height (every node upgrades first — no fork), then rises 5→6→7→8 as sustained difficulty crosses ~8×-spaced thresholds, and eases back if hashrate falls (self-healing — a capacity crash can't re-choke the chain). Backward-safe: existing k=8 blocks stay valid (k=8 ⊃ k=4).
Security is the cumulative work, not k
Raising k is a structural / throughput filter, not cryptographic hardness (β=q/16 is trivial-regime at any k∈{4..8}). Real security is cumulative SHAKE-256 hashcash work = hashrate × time — which needs a live chain to grow. The real hardness lever is a smaller β plus the outstanding audit, not k.
Also in v0.1.0-alpha2
The peering upgrade (--max-peers, --dns-seed, --behind-proxy, IBD-latch release, fresh-miner fork guard), the DAG-ordering consensus-halt fix, and the security-audit fixes. Unaudited; the coin has no value; Bloch is ownerless — a candidate release operators adopt, not a mandate.

2026-07-15 · Bloch peering upgrade

Past the ~50-node wall — three non-consensus changes.

PoW, block validation, serialization, and GhostDAG are untouched. The changes are operator knobs and a mining-readiness guard:

--max-peers <N>
The inbound peer cap was a hardcoded 50 — a bootstrap/hub node dropped every newcomer once full (the "~50-node wall"). It is now an operator setting. The public bootstrap runs --max-peers 500; a leaf node keeps it modest.
--dns-seed <host>
Opt-in, Bitcoin-style cold-start: the node resolves a hostname's A/AAAA records and dials them as peers. DEFAULT_SEEDS stays empty — non-privileged: run, or point at, any seed you trust.
Mining-readiness guard
A node told to join a network (has --peer/--dns-seed) no longer mines until it has connected and evaluated the network tip — so a fresh miner can't fork from genesis. Intentional solo/island miners are unaffected. Also fixed an IBD latch that left a synced node paused forever (is_syncing only cleared on a message no peer ever sends).
