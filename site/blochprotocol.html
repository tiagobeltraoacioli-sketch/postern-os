Compliance · the ownerless protocol

The blochprotocol.com domain.

Postern Labs does not maintain, and cannot maintain, a website at blochprotocol.com. This page states why, and it is published here — on Postern's own product site — precisely because Postern does not speak for the protocol.

Why

The protocol has no owner and no official site.

Bloch-SIS-PoW is an ownerless protocol: by design it has no owner, no foundation, no curator, and no official website — it is software plus a documented RPC/API surface, and nothing more. Postern Labs is merely one builder among many on that neutral base.

For compliance, Postern Labs declares it is NOT

  • the owner of the Bloch-SIS-PoW protocol;
  • a representative of the protocol, its users, or its community;
  • a holder of any prerogatives — no authority, no privileged role, no power to decide, to speak officially, or to administer the protocol.

Operating a site at blochprotocol.com would falsely imply an official, representative, or proprietary position that Postern Labs does not hold and does not claim. Doing so would contradict both the protocol's principles and Postern Labs' compliance posture. Postern Labs therefore does not operate that site.

Where the protocol lives

Software, in the open — maintained by its community, not by Postern.

The protocol is public software. Its source lives at gitlab.com/blochsispow-group/BlochSISPoW-project — shown here as text, not as an endorsing link, precisely because there is no official site to recommend. Any website about the protocol, if one exists, should be created and maintained by the community — never by Postern Labs, which does not speak for the protocol.

Postern Labs' product site is this one, posternlabs.com — and it concerns only Postern's products, leaving the protocol as what it is: an ownerless commons. Postern's only economic tie to the base is a disclosed, structurally passive 17% founder premine, which confers no control, administration, or representation. See Postern & Bloch-SIS-PoW for the full separation.

This is a statement of position by Postern Labs, not legal advice. Bloch-SIS-PoW is a pre-mainnet, unaudited, zero-security beta; its coin is not a security and not an asset.

Roadmap · declared target (not shipped)

FFG-BFT finality — activation target: block 1,000,000.

Declared roadmap target — NOT built

This is a direction, not a shipped feature. FFG-BFT exists today only as a compiling, tested design scaffold — not integrated into the node, not audited, and not running. Nothing activates at block 1,000,000 yet. It is a candidate improvement to the ownerless base: nobody mandates it, and it activates only if node operators adopt it. (Only shipped items go on the changelog — this lives here, as roadmap.)

What it is. A post-quantum finality overlay on the ownerless Bloch base — not a base-consensus change. Individual ML-DSA-65 (FIPS 204) signatures, with no BLS, DKG, or aggregation. The committee is the miners, weighted by hashrate (block-share); a checkpoint finalizes when signatures cover > 2/3 of the epoch's frozen weight, and anchors to the base as an ordinary zero-value transaction. Coins do not vote; hashrate does — the base gains no operator.

The target. Block 1,000,000 (~6.8 months of runway at 30-second blocks) is the proposed, coordinated, height-gated activation — when it is ready, not before.

The path — each step gates the next:

  1. Base stable — sync/convergence holding one chain (prerequisite).
  2. Integrate into the node — committee, weighted quorum, BFT0 checkpoint anchoring, wired into consensus and RPC.
  3. Test — unit, integration, and a full-epoch testnet dry-run.
  4. Audit — third-party review; a finality overlay is safety-critical.
  5. Coordinated deploy — adopted by a super-majority of hashrate ahead of the height, so activation is fork-safe.
  6. Activate at block 1,000,000. No "it's ready" claim before then.

Honest limits

This is not settlement finality. The base is a mainnet beta (k-forgeable, 51%-attackable, unaudited), so overall security is min(base, committee). Hashrate-weighted finality is only as decentralized as the hashrate — today concentrated. It mitigates 51% (raising the bar 51% → 67%, plus no-deep-reorg finality below each checkpoint); it does not eliminate it. The BLCH coin is not a security and not an asset.

Standing disclosures

The underlying protocol runs a mainnet beta — unaudited (audit contracted, not done), nascent, low-hashrate and 51%-attackable. The Module-SIS gate is now a difficulty-driven k-ramp (v0.1.0-alpha2): k=4 today, rising 5→6→7→8 as the network's own difficulty grows, easing back if hashrate falls — the Bitcoin model. The ramp is a structural filter, not a security claim: real security is cumulative SHAKE-256 hashcash work — hashrate × time. Nothing here is a certified security product yet.

The coin is not a security and not an asset. No token sale, no listing effort, no price. Disclosed in full: a 17% founder premine (10-year cliff, 40-year vest), structurally passive.
