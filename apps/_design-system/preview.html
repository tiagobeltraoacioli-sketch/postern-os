Accessibility (WCAG 2.1 AA)

  • Color is never the only signal (1.4.1). Every trust/honesty state pairs its color with an uppercase WORD and a distinct dot or glyph (⚠ / ✖).
  • Contrast (1.4.3 / 1.4.11). Text and semantic colors are tuned per theme so body text and UI borders clear 4.5:1 / 3:1. Light-theme accents were darkened specifically for this.
  • Visible focus (2.4.7). A 2px accent focus-visible ring sits on every interactive element, with offset so it never clips.
  • Reduced motion (2.3.3). prefers-reduced-motion hard-kills all animation and transition.
  • Semantics. Native <dialog> gives a real focus trap; the trust helper sets role="status" + aria-live; the honesty strip is role="note"; icon-only controls carry .ps-sr-only labels / aria-label.
  • Hit targets. Buttons are ≥ 32–36px tall and keep visible text labels.

How an app adopts it

  1. Copy tokens.css, components.css, components.js into the app (or inline them — they are CSP-safe, no external anything).
  2. Add an accent class to <html>/<body>, e.g. class="ps-accent-brass"; wrap the app in .ps-root.
  3. The tokens read the same data-theme the apps already toggle — so the existing theme button keeps working. Or call PosternDS.theme.init() and mark the button data-ps-theme-toggle.
  4. Replace bespoke buttons/cards/badges with .ps-* classes incrementally — the prefix means old and new styles coexist during migration.
  5. For any trust surface, use <div class="ps-trust"> + PosternDS.trust(el, state, why[, PosternDS.VERIFIED_OK]). Green requires the sentinel — a caption can't fake it.
