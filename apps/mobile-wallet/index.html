About & honest limits

What this is

A touch-first reference-prototype UI for a Bloch mobile wallet: balance, receive, send, key & recovery management, and the phone-as-signer WYSIWYS approve flow. A live layer (wallet-live.js + a WebAssembly build of the node's bloch-crypto) makes it a real post-quantum wallet — genuine keys, signatures, keystore and node RPC. It is UNAUDITED and not production software; a browser software keystore, not a hardware enclave.

Honest limits

  • Software keystore. Keys live in this browser tab, not in hardware. Hardware-backed StrongBox / Secure Enclave storage is the labeled goal, not what this prototype does.
  • Two layers. The inline demo core is illustrative (placeholder signature, no live node). The live layer (wallet-live.js) is real: once you create or import a wallet it computes genuine hybrid Falcon-1024 ‖ ML-DSA-65 signatures via the WebAssembly build of the node's bloch-crypto (keygen byte-verified against the node's pinned KAT).
  • No real funds — but a real, live wallet. Before unlock, balances/height/addresses are illustrative and no network call is made. After unlock, the live layer reads real balance/UTXOs and can broadcast over JSON-RPC through the same-origin /rpc proxy, which forwards to the canonical node (connect-src is 'self' only — no third-party host). No telemetry. The base chain is small, unaudited and k-forgeable today — treat BLOCH as having no value.
  • Fee is unverifiable from tx bytes. Transaction inputs carry no amounts, so a declared fee is passed through and labeled unverifiable, never shown as ground truth.
  • Fail-closed. A request the phone cannot honestly display (undecodable, or a multi-output transfer that a single-recipient card would under-display) is refused, not guessed.

The RPC seam

The inline demo core builds and parses JSON-RPC bodies exactly as Bloch core does — getbalance, getblockcount, sendrawtransaction — but its own network adapter stays disabled. The live layer (wallet-live.js) wires a real JSON-RPC client (getbalance / getutxos / sendrawtransaction) to a configurable node endpoint; it degrades gracefully when the node is unreachable (last-known values, "node unreachable"). A plain-http:// node will be blocked from an https page by mixed-content and CSP — it needs HTTPS or a same-origin proxy.
