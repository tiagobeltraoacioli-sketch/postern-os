B·1 Nested access layers

Every layer names its parent. The engine's cardinal rule: no layer widens its parent — a child's scopes must all be covered by the parent (read:* covers read:eu; * covers anything). A layer that exceeds its parent is rejected before it can exist.

Layer tree — current tenant view

B·2 Chinese walls · Brewer–Nash Legal: DPO/counsel

Conflict classes group competitors. The rule is history-based and mandatory: the first member a subject touches binds them; every competitor in that class is then permanently barred — there is no override button, and each binding is logged with a justification. Unbinding is an audited act, not a click.

A wall is a technical plus contractual plus supervisory control. The engine never releases a barred layer's keys — but no software stops a human photographing a screen. The console demonstrates and audits the model; it does not replace the covenant.

B·3 Per-tenant scoping — firmament-grade isolation

Each tenant sees only its own strand of the layer tree. Selecting a tenant re-scopes every panel above and below the firmament: the tree, the subjects, the trail. The governor's all view is the only place strands are seen side by side.

B·4 Corporate license — import & device sub-mint real Ed25519 · offline

Paste the vendor-signed master bundle from /license/master (via Gramota or the Business console). Ezekiel 1 runs the real verifyChain gate offline (WebCrypto Ed25519 — makes no network call): a valid vendor → master chain with a 9-digit DUNS unlocks corporate-master and derives the tenant id t-fnv1a64(org,duns). Anything else stays a demo-only preview — fail-closed, never corporate-master. The personal (parental) edition is unaffected and never imports anything.

The bundle's master_private_key_pkcs8 is kept in memory only — never written to localStorage, never sent anywhere. It signs device sub-tokens locally.

device sub-tokens · chained under the master

Mint a signed device sub-token (Ed25519, signed by the org master key) carrying a BLP clearance. Each sub has sub.exp ≤ master.exp; the device app verifies the offline chain vendor → master → sub. Editing a minted token's clearance breaks its signature.

B·5 Bell–LaPadula clearance lattice MLS · read-only lattice

Every subject carries a clearance; every layer carries a data classification (public → secret). The mandatory rules are enforced at the access-decision point below — no read up (a subject may not read data above its clearance) and no write down (a subject may not write into a layer below its clearance, preventing exfiltration). The decision also consults the Brewer–Nash walls (B·2): a barred conflict class denies outright. All fail closed.

    Privacy — what leaves this device
    

      
Nothing of yours leaves. The only network request this console makes is a same-origin GET of the local ezekiel1.wasm engine served beside this page (connect-src 'self') — no cross-origin request, no Postern server, no telemetry, no phone-home. Your policy state persists only in this browser's localStorage, on your machine, and is never sent anywhere. There is no BYO-key or AI path here; nothing you declare is sent to any model.

      
The honest caveat: this is defense-in-depth, not "100% private" and not "100% secure." localStorage is readable by anyone who can open this browser profile or unlock this device, and a compromised browser or OS can read it too. No web page can promise otherwise.

      
Advisory only. This page declares and displays the access policy; the Rust engine on Postern OS is the authority that actually enforces it, fail-closed. Sovereignty stays with the data owner.
